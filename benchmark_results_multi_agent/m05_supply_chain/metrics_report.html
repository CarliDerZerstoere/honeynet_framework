Metric Glossary

End-to-End Success
A run that passed all five pipeline stages: world model extraction, config validation, plan generation, infrastructure deploy, and runtime verification. This is the primary KPI.
World Model Valid
The LLM successfully extracted a structured deployment model (systems, zones, dependencies) from the input prompt. Failures here mean the LLM output could not be parsed.
Container Start Rate
Fraction of expected containers that actually started running after deployment. Calculated as running containers / expected containers. 100% means all containers launched.
Health Check Pass Rate
Post-startup connectivity probes that passed. These check that containers are not just running but actually responding (e.g., HTTP health endpoints, TCP connectivity).
Service Coverage
When a benchmark reference is provided: the fraction of required services (e.g., database, web server, cache) that are present in the deployment. 100% = all required services found.
Benchmark Pass
True only when ALL benchmark requirements are met: 100% service coverage, 100% zone coverage, 100% dependency coverage, and zero placement violations.
Scenario Fit Score
Composite score (0.0–1.0) computed as the equal-weight average of service, zone, and dependency coverage. Halved when placement violations exist. Useful for ranking partially correct results without the all-or-nothing nature of Benchmark Pass.
Error Class
Coarse classification of why a run failed (e.g., port_conflict, invalid_image, llm_schema_error). Shown in the failure column and aggregated in the failure distribution table.
Failure Stage
The earliest pipeline stage where a run failed. Common stages: world_model_validation, config_validation, plan, deploy, runtime_verify.
