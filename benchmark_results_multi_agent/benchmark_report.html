What do these metrics mean?

Service Coverage
How many services required by the benchmark reference are present in the deployment. 100% means all required services (e.g., database, web server, cache) were generated by the LLM.
Zone Coverage
How many network zones required by the benchmark are present. Zones define network isolation boundaries (e.g., DMZ for public-facing services, internal for databases).
Dependency Coverage
Whether required connections between services exist in the deployment plan. For example, a web server must depend on its database so they start in the correct order. Shows n/a when the benchmark defines no dependency requirements.
Placement Violations
Services deployed in zones where they are forbidden by the benchmark reference. For example, a database exposed in the DMZ instead of the internal zone. Zero is the target.
Benchmark Pass
True only when ALL of the above are satisfied: 100% service coverage, 100% zone coverage, 100% dependency coverage, and zero placement violations.
Scenario Fit Score
Composite score (0.0–1.0) computed as the equal-weight average of service, zone, and dependency coverage. Halved when placement violations exist. Useful for ranking partially correct results.
Error Class
Coarse classification of the failure cause (e.g., port_conflict, invalid_image, llm_schema_error). Shown in parentheses after the failure stage.
Plan vs Running
"Plan" metrics evaluate the deployment model before containers start. "Running" metrics evaluate against actually running containers. Running coverage can be lower if containers crash on startup.
